# Risk path

The only route to a simulated fill is `System.on_tick` → strategy signal → `Risk.check` → `PaperExecution.fill` → portfolio. Check order: kill switch; daily-loss latch; stale quote age; valid positive, non-crossed bid/ask and positive sizes; positive size; per-symbol position cap; gross short notional backed by initial virtual capital; paper cash; visible top-of-book size; minimum paper notional. Rejections persist in `risk_events` and appear on the dashboard. The daily-loss latch counts mark-to-market equity against UTC day-start equity, including fees. It resets with the UTC date; the manual kill switch does not flatten positions and does not hide existing exposure. Resume requires an authorized token. Stale data blocks new fills but existing paper positions remain and their marks become old.

The public dashboard is read-only by default. `POST /api/kill-switch` and `POST /api/reset-session` require `X-Control-Token`. Supply a high-entropy secret through environment configuration, never commit it. The reset starts a new session with new virtual capital. The previous one remains stored. For a shared public demo, keep the token private and explain the controls rather than giving every viewer mutable access.

Tests exercise manual halt, daily loss, invalid/stale quotes, and position limits. No UI toggle, strategy decision, or provider message bypasses the risk layer.
